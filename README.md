**An end-to-end fraud detection system for online payments** — engineered, trained, evaluated, and served as a monitored, containerized inference API.

> **Live demo:** https://fraud-shield-gnec.onrender.com/

A portfolio-grade ML engineering project built on the real-world **IEEE-CIS Fraud Detection**
dataset (~590K transactions, fraud ≈ 3.5%). It demonstrates the full lifecycle a fraud model
follows in production: turning raw transaction and identity data into leakage-safe features,
validating models on a **time-based split**, tuning an operational decision threshold,
explaining individual predictions, and monitoring the deployed service for drift.

## What this project demonstrates

- **Leakage-aware feature engineering** — expanding-window aggregates that deliberately
  exclude the current row, so validation metrics reflect real-world performance.
- **Temporal (out-of-time) validation** — training, validation, and hold-out are split by
  time, not at random, to avoid optimistic results.
- **Imbalanced classification** — a defensible baseline (Logistic Regression) versus a strong
  gradient-boosted model (XGBoost), with fraud being a rare event.
- **Operational decisioning** — threshold optimization that trades off false positives
  (annoying good customers) against false negatives (missed fraud).
- **Interpretability** — per-prediction SHAP (TreeSHAP) explanations showing which transaction
  details drove each score.
- **MLOps** — containerized REST API (FastAPI), experiment & model tracking (MLflow), and
  system + data monitoring (Prometheus, Evidently).

## Approach

1. **Ingest & validate** — transaction and identity tables are joined and validated
   (schema, null, range, and temporal-order checks), versioned with DVC.
2. **Feature engineering** — 416 deterministic, documented features, including time-safe
   historical aggregates so the model never sees the future.
3. **Modeling** — a Logistic Regression baseline anchors expectations; an XGBoost model is
   trained with class-imbalance handling.
4. **Evaluation & promotion** — models are scored with fraud-appropriate metrics (PR-AUC)
   on the temporal hold-out and pass through a promotion gate before being registered as the
   champion in MLflow.
5. **Serving** — a FastAPI service scores transactions, returns a risk score + decision,
   and attaches SHAP risk factors; the service is hardened and containerized.
6. **Monitoring** — Prometheus scrapes system metrics (`/metrics`); Evidently runs periodic
   data-drift checks against a reference distribution.

## Results

| Model                       | Hold-out PR-AUC |
|-----------------------------|-----------------|
| Logistic Regression (baseline) | 0.195       |
| XGBoost (champion)             | **0.511**   |

The champion operates at a tuned threshold of **0.798**, balancing recall against precision
on a heavily imbalanced problem. A reproducible model card is generated by
`scripts/build_report.py` → `data/artifacts/final_evaluation.md`.

## Live demo

Open **https://fraud-shield-gnec.onrender.com/** and:

- Click **New random transaction** to load a real, pre-scored transaction.
- Edit any field and click **Check fraud** to see the risk score, decision, and the
  top risk factors behind it.
- Hover any technical term (e.g. `card1`, `TransactionAmt`) for a plain-English meaning, or
  open **"What do these terms mean?"** at the bottom.

> Note: the demo runs on a free tier, so the first request after a period of inactivity may
> take ~30–60s to wake up.

## Quickstart

```bash
# Environment
python -m venv .venv && .\.venv\Scripts\Activate.ps1
pip install -e ".[base,ml,serving,mlops,dev]"

# Reproduce the whole pipeline + regenerate the model card
dvc repro
python scripts/build_report.py

# Quality gate
ruff check src tests scripts
python -m mypy src
python -m pytest -q

# Serve locally
docker compose up -d            # image: fraud-intel-api:latest
# GET  /health
# POST /predict  { "transaction_id": "...", "features": { ... } }
# GET  /metrics  (Prometheus)
```

> `dvc repro` needs the IEEE-CIS dataset in `data/raw` (plus a `dvc pull` to populate
> `data/artifacts`); `docker compose up -d` works without it — the trained model is already
> baked into the `fraud-intel-api:latest` image.
